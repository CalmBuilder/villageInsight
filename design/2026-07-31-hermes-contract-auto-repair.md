# Hermes 识别契约自动修复与降级

## 问题

模板差异识别可能返回可解析但不满足后端业务契约的结果。例如
`match_type = none` 时遗漏 `template_suggestion`。当前实现会调用推理模型重写
整个分块；如果修复响应又不符合 JSON Schema，识别任务失败并转为人工处理。

这类失败不代表源文件、物理证据或字段判断不可用。尤其是模板建议属于可治理的
模板元数据，现有临时模板逻辑已经能够在建议缺失时生成幂等代码和名称，并以
`unclassified` 元数据继续原始 JSONB 部分入库。

## 目标

- 重试时向模型提供结构化错误、明确修复目标、上次结果和不可修改约束。
- 只修复被拒绝的契约部分，保留已经有效的字段和布局判断。
- 修复模型返回非法 JSON 时，保留上一次已通过 JSON Schema 的候选结果。
- 模板建议缺失时自动使用现有临时模板降级路径，不要求人工重试。
- 未知来源列、伪造坐标、字段覆盖缺失等可能破坏证据完整性的错误继续阻断。
- 错误诊断只记录 Schema 路径和错误类型，不记录原始人员值。

## 执行链

1. 快速模型返回 `TemplateDiffChunkResult`。
2. 后端执行确定性业务契约校验。
3. 校验失败时构造结构化修复请求：
   - `validation_error.code` 和脱敏错误信息；
   - `repair_target` 中的必需路径、字段和预期结果；
   - `constraints` 中的保留项和禁止项；
   - `previous_result`。
4. 推理模型只修复目标契约，并再次接受 JSON Schema 和业务契约校验。
5. 如果修复响应本身不符合 JSON Schema：
   - 对可降级的 `TEMPLATE_SUGGESTION_REQUIRED`，保留首次候选；
   - 对证据、坐标、字段覆盖等安全错误，继续抛错并由任务队列处理。
6. 最终模板建议仍缺失时，增加
   `HERMES_TEMPLATE_SUGGESTION_MISSING` 治理原因，创建幂等临时模板并继续部分入库。

## 可观测性

`HermesInvalidResponseError` 包含有限数量的 Pydantic 错误路径和错误类型，以及
响应长度；不包含响应原文、输入样例或字段值。运行时的内部 JSON 修复请求也要
携带这些结构化错误和“匹配目标 Schema”的明确目标。

## 验收

1. `match_type = none` 且首次缺少模板建议时，会发送结构化定向修复请求。
2. 定向修复返回非法 Schema 时，识别仍生成带治理原因的提案。
3. 后续能够复用现有临时模板路径继续部分入库。
4. 未知来源列等不可降级错误仍使识别失败。
5. Hermes 运行时错误可定位 Schema 路径和错误类型，但不泄露原始响应。
6. 聚焦识别和运行时测试、Ruff 与 mypy 通过。
