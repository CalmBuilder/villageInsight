# README 快速开始与 settings.key 启动改造方案

## 目标

1. 根 README 按用户实际使用优先级组织，启动、模板导入、样例导入和问数验证位于最前。
2. 宿主机进程模式同时支持本机浏览器和虚拟机外的宿主机浏览器访问。
3. 新环境自动准备 `settings.key`，已有加密凭据的环境不得因密钥缺失而静默生成新密钥。
4. 宿主机进程模式和全容器模式复用同一个 `data/secrets/settings.key`。

## 密钥策略

- 启动预检先检查 `settings.key` 是否存在且为有效 Fernet key。
- 密钥存在时只复用和校验，不替换内容。
- 密钥不存在、数据库也没有模型密文时，使用原子独占创建生成新密钥。
- 密钥不存在但数据库已有 `llm_configurations` 或 `llm_provider_credentials` 密文时，
  不生成新密钥，应用以模型功能降级模式继续启动；设置页要求恢复原密钥或重新录入 Key。
- 宿主机启动在迁移后执行预检。
- 全容器启动增加一次性 `secret-init` 服务。该服务短暂以 root 运行，只负责创建或检查
  密钥及设置共享权限；Worker 保持只读，API 只为明确重新录入 Key 的恢复路径保留写权限。
- 不打印密钥内容，只允许输出短指纹用于运维对账。

## 虚拟机访问

- Web 继续监听 `0.0.0.0:9137`。
- API 继续只监听虚拟机内部 `127.0.0.1:9138`，不要求向宿主机开放。
- 虚拟机内访问 `http://localhost:9137`。
- 宿主机访问 `http://<虚拟机IP>:9137`；桥接网络直接使用虚拟机 IP，NAT 网络配置
  9137 端口转发，并放行虚拟机防火墙 TCP 9137。
- 不把 `0.0.0.0` 写成浏览器访问地址，它只是监听地址。

## 验收

- `./app.sh` 的测试确认迁移、账号初始化和密钥预检均被调用。
- 新数据库无密钥时能够生成 0600 密钥。
- 数据库存在模型密文而密钥缺失时预检成功返回降级状态，且不产生新密钥文件。
- 已有有效密钥不会被覆盖。
- 全容器 Compose 配置包含一次性密钥初始化依赖；Worker 密钥挂载保持只读，API 只为
  明确重新录入 Key 的恢复路径保留写权限。
- README 所有本地链接有效，示例命令与代码一致。
- README 明确给出虚拟机内和宿主机两种访问地址。
